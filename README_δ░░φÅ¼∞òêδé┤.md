# 이움레터 — 배포 안내

이 폴더 자체가 배포 결과물입니다. **빌드 과정이 필요 없습니다.**

## Netlify 배포 (가장 간단한 방법)

1. ZIP 압축을 풉니다.
2. https://app.netlify.com/drop 에 압축을 푼 폴더를 통째로 끌어다 놓습니다.
   (기존 사이트를 교체하려면 Netlify 사이트 → Deploys → "Drag and drop" 영역에 폴더를 놓으세요.)
3. 배포된 주소에서 `/`, `/wedding`, `/obituary` 가 열리는지 확인합니다.

Git 저장소로 배포할 때는 이 폴더를 저장소 루트로 올리면 됩니다.
`netlify.toml`에 publish = "." 와 빌드 명령 없음이 이미 설정돼 있습니다.

## v13 청첩장 · 부고장 통합 수정

공통: 미리보기 클릭 → 정확한 입력칸 이동, 부고장 미리보기 오버레이 스크롤바, 메뉴 안내 문구 통일, 신규 제작 시 기본 항목 전체 ON.
청첩장: 항목 관리 자동 열기 · 첫 안내 팝업 제거, 교통수단별 표시 ON/OFF · 위치 기반 교통정보 자동 조회, 당일 팝업 주소 복사 · 교통 안내 정확한 이동, 제작자 미리보기 제출 비활성화, 항목 추가 단순화.
부고장: 마음 전하실 곳 기본 ON · 입력 안내, 위치 기반 주차정보 자동 입력, '조문 안내 메뉴에 표시' 연동, 플로팅 버튼 → 조문객 안내 화면 먼저 표시 후 클릭 편집.
자동 조회 · AI 분석은 서버 함수를 연결해야 실제로 동작합니다(미연결 시 '확인 필요'로 표시하고 정보를 만들지 않음). 자세한 내용과 설정 방법은 `docs/v13_청첩장·부고장_통합수정_보고서.md`.

## 데이터 저장 방식 (최신)

  - 데모 시나리오: 초대 문구(연애 기간·스타일·길이 추출) · 감사 인사 · 교통/주차 안내 · 참석 여부 안내 · 마음 전하기 안내 · 추가 항목 설명 문구 · 후속 수정(짧게/담백하게/정중하게/친근하게/다른 버전) · 당일 일정 카드(개수·카드/타임라인/목록 변경) · 우천 시 안내 · 드레스코드 · 레이아웃별 빈 항목 · 섹션 순서 변경/숨김/표시(승인 후 적용) · 완성도 점검(실제 입력값 기준) · 전체 문구 분위기 변경(기존/제안 비교 후 선택 적용)
  - 지원하지 않는 요청은 "현재 데모에서는 문구 작성, 일정 안내 추가, 우천 안내 추가, 섹션 구성 변경 등을 체험하실 수 있어요."와 예시 질문 버튼으로 안내
  - AI 답변만으로는 아무것도 바뀌지 않으며, '이 문구 적용하기 / 이 항목 추가하기 / 변경 적용하기'를 눌러야 반영. 적용 위치를 바꿀 수 있는 선택 상자 제공. 적용 후 '되돌리기'
- **+ 항목 추가**: 텍스트형 · 카드형(2/3/4개로 시작, 최대 6개) · 타임라인형(순서 변경) · 이미지+텍스트형 · 목록형 · 버튼·링크형(https 주소만 허용, 안전하지 않은 링크는 하객 화면에 숨김). 기본 항목과 같은 목록에서 펼치기·숨김/표시·끌어서/↑↓ 순서 변경·삭제(확인 후, 되돌리기 가능)
- **되돌리기**: 편집기 상단 '↶ 되돌리기' — AI 적용·문구 추천·항목 추가/삭제·구성 변경을 최근 20단계까지

### 데이터 구조 (직접 추가 · AI 추가 공통)
- 섹션 순서·표시: 기존 `sections: [{ id, on }]` 배열에 사용자 섹션 id(`cx-…`)가 함께 들어갑니다.
- 섹션 내용: `data.customSecs[id] = { id, layout, title, desc, items:[{id,time,title,desc,icon,image}], buttons:[{id,label,url}], image, source:'manual'|'ai' }`
- 이전 저장본(섹션 10개, `customSecs` 없음)도 그대로 불러옵니다. 템플릿을 바꿔도 사용자 섹션 내용은 유지됩니다.
- 저장은 기존과 같이 **이 브라우저(localStorage)에만** 됩니다. 다른 기기·브라우저와 동기화되지 않습니다. 용량이 부족하면 사진(추가 항목 이미지 포함)은 임시 저장에서 제외됩니다.

### 실제 AI 연동 시 필요한 작업
1. 서버 함수 준비: `docs/server-example/ium-ai-function.js`를 `netlify/functions/ium-ai.js`로 옮기고, `/api/ium-ai` 대체 규칙을 SPA 규칙보다 위에 추가
2. API 키는 Netlify 환경 변수(`ANTHROPIC_API_KEY`)에만 저장 — 프런트엔드 코드·저장소에 넣지 않기. 사용할 모델 이름은 `IUM_AI_MODEL`로 지정(제공사 문서에서 현재 모델명 확인)
3. `app/ium-ai.js`의 `config.mode`를 `'remote'`로 변경 (서버 오류 시 자동으로 데모 응답으로 대체)
4. 서버는 `app/ium-ai.js` 상단의 응답 형식을 돌려주면 되고, 프런트엔드가 `sanitizeResponse`/`validateCommands`로 검증한 뒤 기존 `runCmds`로 적용 — 편집기 수정 불필요
5. 운영 시 권장: 요청 횟수 제한, 사용자 인증, 개인정보(이름·연락처) 전송 범위 검토, 응답 JSON 형식 실패 시 재시도

### 동작
- 오른쪽 아래 원형 버튼(안내) → 빈소 · 주차 · 발인 · 길찾기 4개 버튼이 펼쳐짐, 다시 누르면 접힘. 상세 팝업은 '닫기' 버튼·Esc·(받는 분 화면) 바깥 영역으로 닫힘
- 받는 분 화면: 화면 오른쪽 아래에 고정(스크롤해도 유지). PC에서는 부고장 폭(480px) 기준 오른쪽 아래
- 제작 화면 미리보기: 휴대폰 화면 안 오른쪽 아래에 고정. 모바일 편집기의 축소 미리보기에서는 메뉴가 가로로 펼쳐지고, '전체 화면 미리보기'에서는 받는 분 화면과 같은 크기로 체험 가능
- 정보는 기존 입력값(장례식장명 · 주소 · 호실·상세 위치 · 발인 일시 · 입관 일시 · 장지)을 그대로 읽어 즉시 반영. 층수는 '호실·상세 위치'(또는 주소)에 'N층/지하 N층/B1'이 있을 때만 따로 표시
- 정보가 없으면 버튼은 그대로 두고 팝업에서 '확인된 정보가 없습니다' / '발인 정보가 없습니다' / '확인된 주차장 정보가 없습니다' 표시
- 주차 정보는 '주차' 버튼을 눌렀을 때만 조회·표시하며 부고장 본문·편집 화면에는 나타나지 않음
- 근조화환: 기존 '근조화환 보내기' 버튼 위치·기능 그대로. 화환 플로팅 버튼은 추가하지 않음

### 지도 연결
| 환경 | 동작 |
|---|---|
| 제작·관리 화면 미리보기 | 편집 화면이 사라지지 않도록 항상 **새 탭의 웹 지도** |
| PC 받는 분 화면 | 카카오맵 · 네이버 지도 · 구글 지도 웹을 새 탭으로 |
| Android | `intent://`로 카카오맵/네이버 지도/티맵 앱 실행, 앱이 없으면 브라우저가 웹 지도로 이동 · 구글 지도는 https 링크 |
| iOS | 앱 주소로 실행 시도 → 1.6초 안에 앱이 열리지 않으면 '웹 지도로 열기' 버튼 안내 · Apple 지도·구글 지도는 https 링크 |

기본 지도 앱을 자동으로 정할 수 없기 때문에 길찾기에서 지도를 고르는 방식입니다. 메인 '길찾기'의 목적지는 장례식장, 주차장 카드의 '지도' 버튼은 해당 주차장입니다.
좌표가 없는 목적지(직접 입력한 주소)는 주소 검색으로, 좌표가 있는 목적지(API로 조회된 주차장)는 경로 안내 주소로 엽니다.

### 주차장 자동 조회 — 현재 상태와 연결 방법
현재 배포본에는 **지도 API 키가 없어서 실제 주차장 조회는 꺼져 있습니다.**
- 실제 장례식장 주소 → '확인된 주차장 정보가 없습니다' + '지도에서 주변 주차장 검색'(카카오맵 검색 링크) 표시. 미리보기에서만 제작자용 연결 안내 문구가 함께 보임
- 데모용 가상 장례식장(주소에 '가상 주소') → 체험용 예시 주차장 3곳을 **'예시'** 표시와 함께 보여줌 (실제 정보 아님)

연결 방법 (둘 중 하나):
1. **카카오맵 JavaScript SDK** — 카카오 디벨로퍼스에서 앱 생성 → JavaScript 키 발급 → 플랫폼 › Web에 배포 도메인 등록 → `app/ium-guide.js`의 `config.kakaoJsKey`에 입력
   (또는 `index.html`에서 이 스크립트 앞에 `<script>window.IUM_GUIDE_CONFIG={kakaoJsKey:'...'}</script>`)
2. **서버 함수** — `docs/server-example/ium-parking-function.js` 안내대로 배포 후 `config.parkingEndpoint = '/api/parking'` (REST 키는 Netlify 환경 변수에만 보관)

조회 방식: 장례식장 주소(실패 시 이름)로 좌표를 찾고 → 반경 700m 주차장(카카오 카테고리 PK6)을 가까운 순으로 → 이름이 장례식장과 겹치거나 주소가 같은 곳을 '장례식장 주차장'으로 맨 위에 표시.
**카카오 장소 검색에는 무료/유료 여부·요금·운영시간이 없습니다.** 그래서 연결 후에도 이 항목은 '확인된 정보 없음'으로 나오며, 표시하려면 공공데이터(전국주차장정보표준데이터 등)를 서버에서 대조해 채워야 합니다. 확인되지 않은 값은 만들어 넣지 않습니다.

### 저장 방식의 제약 (변경 없음)
부고장 데이터는 기존과 같이 **이 브라우저(localStorage)에만** 저장됩니다. 그래서 `/obituary/view/{id}` 받는 분 화면은 **부고장을 만든 같은 브라우저에서만** 열립니다.
다른 사람의 휴대폰에서 같은 링크를 열면 부고장이 보이지 않으며(퀵 가이드도 마찬가지), 실제 공유에는 서버 저장(DB)과 공유 링크 발급 작업이 별도로 필요합니다.

## 부고장 '변경 안내 배너' · '조문 예절 안내' (이번 업데이트)

빌드 과정은 여전히 필요 없습니다. 수정한 파일은 `svc-obituary.dc.html` 하나이며, 라우팅·`netlify.toml`·`_redirects`·청첩장·통합 홈·퀵 가이드(`app/ium-guide.js`)는 그대로입니다. 근조화환 플로팅 버튼은 추가하지 않았습니다.

### ① 중요 정보 변경 안내 배너
- **감지 대상**: 장례식장 이름 · 장례식장 주소 · 빈소 호실 · 발인 날짜 · 발인 시간 (이 다섯 가지만)
- **감지 시점**: 이미 발행한 부고장을 '수정 내용 저장하기'로 저장할 때, 저장돼 있던 최신 값과 비교. 입력 중에는 묻지 않으며 최초 발행 시에는 배너가 없습니다.
- **확인창**: "장례 정보가 변경되었습니다. 변경된 내용을 조문객에게 안내할까요?" → `안내 배너 표시` / `표시하지 않기`. 어느 쪽을 눌러도 수정 내용은 저장됩니다. 여러 항목을 한 번에 바꾸면 한 번만 묻습니다.
- **문구**: 최신 값만 짧게 — "빈소가 5호실로 변경되었습니다." / "장례식장이 ○○장례식장으로 변경되었습니다." / "발인 날짜가 11월 8일로 변경되었습니다." / "발인 시간이 오전 8시로 변경되었습니다." / "장례식장 주소가 변경되었습니다. [최신 주소 보기]"(퀵 가이드의 빈소 안내를 열어 최신 주소 표시). 조사(로/으로)는 자동으로 맞춥니다.
- **통합 규칙**: 배너는 항상 하나. 새 항목은 추가, 같은 항목은 최신 값으로 교체(과거 값 누적 없음). `표시하지 않기`를 고르면 새 항목은 추가하지 않고, 이미 배너에 있는 항목이 다시 바뀌었으면 최신 값으로 맞추거나(값을 지운 경우) 제거합니다.
- **종료**: 부고장 관리 화면과 수정 화면 상단의 '변경 안내 배너' 영역(배너가 표시 중일 때만 보임) → `배너 표시 종료`. 종료하면 항목이 모두 지워져 이후에 다시 나타나지 않습니다.
- 수정 화면 미리보기에서는 배너에 있는 항목을 입력 중인 최신 값으로 맞춰 보여줍니다(새 항목은 저장 후 선택에 따라 추가).

### ② 종교별 맞춤 조문 예절 안내
- **편집**: 부고장 만들기 › 3. 내용 입력 › `조문 예절 안내` 섹션(다른 섹션과 같은 아코디언). 표시 스위치(켜기/끄기) · 장례 종교 선택(일반/무종교 · 불교식 · 기독교식(개신교) · 천주교식) · 6개 항목(종교별 조문 예절 · 조문 순서 · 복장 · 조의금 · 위로의 말 · 주의할 행동)
- 항목별로 문구 수정 · `＋ 문구 추가` · 문구 삭제(−) · 표시/숨김 스위치 · `기본 문구 복원`
- **접기·펼치기**: 처음에는 표시 스위치와 `상세 설정 및 내용 편집` 버튼(현재 종교 · 표시 항목 수 · 수정 여부 요약)만 보입니다. 버튼을 눌러야 종교 선택과 6개 항목 목록이 펼쳐지고, 각 항목도 제목만 보이는 아코디언이라 하나를 펼쳤을 때만 그 항목의 문구 편집 · 표시/숨김 · 기본 문구 복원이 나타납니다(한 번에 한 항목). 접어도 수정 내용은 유지되며, 접기는 편집 화면 표시만 바꿀 뿐 조문객 화면의 켜짐/꺼짐에는 영향이 없습니다.
- 장례 종교는 '고인 정보'의 종교와 **같은 값**입니다(첫 문구 '별세/소천/선종'과 예절 안내가 서로 어긋나지 않도록). 직접 수정한 항목이 있는 상태에서 종교를 바꾸면 `수정한 내용 유지` / `새 기본 문구로 교체` / `취소`를 묻습니다. 수정하지 않은 항목은 새 종교의 기본 문구를 자동으로 따릅니다. AI 채팅 등으로 종교가 바뀐 경우에는 섹션 안에 같은 선택 안내가 표시됩니다.
- **조문객 화면**: 본문 맨 아래(조문 메시지 다음)에 `[책] 조문 예절 안내 [›]` 버튼 하나와 보조 문구. 누르면 모바일은 바텀시트, PC는 가운데 팝업(페이지 이동 없음). 항목은 탭으로 전환, 긴 내용은 팝업 안에서만 스크롤, 닫기 버튼 · Esc · 바깥 영역으로 닫힘.
- 섹션을 끄거나, 켠 항목에 문구가 하나도 없으면 버튼이 숨겨집니다.
- 미리보기에서도 같은 버튼·팝업이 휴대폰 화면 안에서 열립니다(`미리보기에서 열어 보기` 버튼으로 바로 확인 가능).

### 데이터 구조 (부고장 객체에 추가)
- `notice: { items: [{ key: 'hallName'|'hallAddress'|'room'|'funDate'|'funTime', val, at }], updatedAt, endedAt? }` — 저장된 부고장에만 보관(편집 초안에는 두지 않음)
- `etq: { on, items: { rite|order|dress|money|words|avoid: { on, lines: null|[문구], base } } }` — `lines: null`이면 현재 종교의 기본 문구 사용
- 이전에 만든 부고장(위 필드 없음)도 그대로 열리며, 예절 안내는 기본값(켜짐 · 기본 문구)으로 표시됩니다.

### 저장 방식의 제약 (변경 없음)
두 기능 모두 기존과 같이 **이 브라우저(localStorage)** 에 저장됩니다. 새로고침 후에도 유지되지만, 다른 기기에서 같은 링크를 열면 부고장·배너·예절 안내가 보이지 않습니다. 실제 공유에는 서버 저장(DB)과 공유 링크 발급이 별도로 필요합니다.

## 데이터 유지 · 초기화 방식 (이번 업데이트)

디자인·레이아웃·템플릿·기능은 바꾸지 않았고, **데이터를 어디에 보관하는지만** 바꿨습니다.

### 동작
| 상황 | 결과 |
|---|---|
| 제작 단계 이전/다음, 진행 단계 클릭, 템플릿 변경, 편집 항목 이동 | 입력 내용 유지 |
| 제작자 ↔ 하객(조문객) ↔ 관리자 화면 이동, 통합 홈 다녀오기 | 같은 데이터를 공유·유지 |
| 브라우저 뒤로 가기 · 앞으로 가기 | 유지 (History API로 페이지를 다시 불러오지 않음) |
| 새로고침 · 탭 닫고 재접속 · 링크로 새로 접속 · 다른 브라우저/기기 | 최초 상태로 시작 (기본 샘플 데이터·템플릿만 표시) |

초기화 대상: 청첩장·부고장 제작 정보, 임시 저장본, 이움 AI 대화, RSVP 응답, 방명록, 하객 사진, 조문 메시지, 감사장, 발송·주문 기록, 관리자 통계 등 시연 중 생긴 모든 데이터.

### 구현
- `app/router.js` — 메모리 저장소 `window.IumMem`(getItem/setItem/removeItem, localStorage와 같은 사용법) 추가. 라우터의 '서비스별 마지막 화면'도 sessionStorage 대신 메모리에 보관.
- 페이지가 열릴 때 이전 버전이 남긴 `iumletter:` / `iumletter-` 로 시작하는 localStorage·sessionStorage 키를 삭제 (예전에 저장된 입력이 다시 나타나지 않도록). 다른 키는 건드리지 않습니다.
- `svc-wedding.dc.html`, `svc-obituary.dc.html` — 저장·불러오기 코드가 `window.localStorage` 대신 `window.IumMem`을 사용. 세 서비스는 한 페이지 안에 계속 마운트되어 있으므로 화면 전환 중에도 같은 상태를 공유합니다.
- '이 브라우저에 보관/저장' 안내 문구를 '이용하는 동안 유지 · 새로고침하면 초기화'로 맞췄습니다.
- 서버 저장: 없음. `docs/server-example/`의 함수(AI·주차장 조회)는 기본 배포에서 동작하지 않으며, 동작하더라도 조회만 하고 입력 정보를 저장하지 않습니다.

### 참고
- 부고장 받는 분 화면(`/obituary/view/{id}`) 링크는 같은 탭에서 사이트를 이용하는 동안에만 열립니다. 새로고침하거나 다른 사람이 열면 '정보가 없거나 삭제되었어요'가 표시됩니다(의도된 동작).
- 다른 사이트로 나갔다가 브라우저 뒤로 가기로 돌아올 때, 브라우저가 페이지를 메모리째 복원(bfcache)하면 이전 화면이 그대로 보일 수 있습니다. 링크로 다시 접속하면 항상 초기 상태입니다.
